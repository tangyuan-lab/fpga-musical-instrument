正弦波已经能听、能按键、能两个声部一起响，但它不像乐器。今天开始处理音色。

## 实时合成约束

课题要求逐样本在 FPGA 上实时合成。`generate_timbre_v1_tables.py` 生成三张 1024 点周期谐波表，声部按相位和包络实时读取。

起音表谐波最丰富，最亮，负责敲击的那一下；主体表谐波少一些，声音变柔；尾音表最柔，负责
余韵。

FPGA 在平均 48 kHz 的节拍下推进 DDS 相位、读这三张表、逐样本混合，同时算击弦包络和松键
阻尼。起音、主体、尾音之间的过渡是随时间连续变形的，不是三段硬切。

## 几个我当时调过的地方

起音的平滑上升约 1.3 ms。直接从零跳到满音量会有明显的"啪"，1.3 ms 在 48 kHz 下大概是
62 个采样帧。

连续快速按键时，从前一音的实际音量平滑回升。我一开始是每次 `note_on` 都把包络重置到固定
起点，结果快速连按的时候后面的音一个比一个轻——因为前一个音还没衰减完，包络起点却是按新音
算的，两次衰减叠在一起了。改成从上一次的实际电平继续往上走就没这个问题了。

起音在约 0.17 秒内逐渐转向主体音色。高频留太久会变成持续的"嘶"声，不像钢琴。

按住的时候自然衰减，松键后阻尼加快。这是钢琴和弦乐的区别：钢琴的琴弦在自己衰减，松键是踩下
制音器让它更快停。

力度同时决定起音响度和亮度。数字力度 0～127，板上试听时固定在 112/127。

功放前那一级 `audio_gain` 对本模块的原始样本放大 4 倍，串行 PCM 峰值约 22,580，离 16 位
削波界限 32,767 还有余量。

## 验证

```powershell
vsim -c -do run_timbre_v1.do
```

testbench 从 PT8211 串行引脚解码左右声道，检查四音顺序、起音/衰减/松键、力度 32 和 127 的
响度差、复位静音和不削波。本次重跑通过。

原始工程把仿真 PCM 导成了试听 WAV（`previews/piano_four_notes_v1.wav`），频谱主峰约为
439、494、521、590 Hz；首音高频能量占比从 0.041 降到 0.006，高频确实在往柔里走。四音峰值
都约 22,500，没有出现快速按键后逐音变小的情况。

原始工程记录：Gowin 综合通过，Fmax 91.814 MHz，3 个 BSRAM + 3 个 DSP。

仿真验证了高频衰减、包络连续和输出未削波；主观音色需要试听确认。
