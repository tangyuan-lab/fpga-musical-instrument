# 钢琴32音递进屏幕接口 v1

适用版本为`0x5c9cde6a`，工程入口为`workstation_r6_piano32_bt.gprj`。屏幕依据完整构建身份、能力与会话字段匹配本接口。

## 传输和进入页面

屏幕UART仍为115200/8N1，命令仍为五字节 `A5 5A OP VALUE CHECK`，校验字节为 `FF XOR OP XOR VALUE`。先发送 `60 08` 进入测试视图；此操作不启动演示。FPGA在此视图发送下面的P00至P15状态，其他页面的字段定义不变。

屏幕必须先接收到一份完整、新鲜且构建身份与交付清单一致的v1状态，才能允许用户点击开始。页面打开、恢复连接、下载TFT都不自动启动；开始动作由用户点击产生，并按下述请求号与会话规则确认。

## 控制

| OP | VALUE | 行为 |
|---|---|---|
| 67 | 请求号1..255 | 从低到高启动钢琴48..79，旧请求号与重复请求不重新开始 |
| 6E | 当前请求号 | 只为屏幕拥有的同请求演示保活 |
| 6F | 当前请求号 | 只停止同请求的屏幕演示 |
| 62 | 0 | 无条件停止测试，保留原急停入口 |
| 60 | 0..3 | 离开测试并按原逻辑清音 |

同一次设备上电内，新屏幕请求号必须严格递增，不能回绕或复用。P07提供最后派发的请求号；重连先完整回读，下一次用户点击才使用更大的号。到255后需复位设备再建立新的连接状态，不自动复位。派发不等于实际启动：必须核对实际session变化、owner=2、当前请求号匹配、阶段进入准备/递进；被急停或看门狗抢先取消的请求不得显示已启动。

USB 测试中心使用 `E5:61,2` 启动、`63,0` 保活、`62,0` 停止。串口屏使用带请求号的入口，兼容旧屏幕的 `61,2` 命令。带请求号的屏幕会话只接受同一来源且请求号匹配的心跳。HC-05 按蓝牙命令白名单提供参数控制与状态回读。钢琴递进由 USB 或串口屏控制。

同沿USB测试停止优先于屏幕启动；其他同沿测试命令保持屏幕优先。USB协议ACK仅表示命令接收，实际会话以回读为准。原硬件急停、模式退出和750ms看门狗仍优先，未放宽。屏幕建议每100ms发送一次同请求保活；回传与接收独立，不等待图形或进度包才发心跳。

## 原子状态

使用已有 `rxP00.val` .. `rxP15.val`，每个数均小于2^31。发送器在帧首同一时钟沿锁存全部15个数据字；P15最后提交。收到各数据字时只写暂存区，P15验证成功后一次更新显示，不能显示半帧状态。

| 字段 | 定义 |
|---|---|
| P00 | `0x50333201`，P32接口v1标识 |
| P01 | `0x0000000F`：递进、真实完成计数、帧快照、请求号控制 |
| P02/P03 | 构建ID低16位/高16位，拼接完整32位 |
| P04/P05 | 实际测试session低16位/高16位 |
| P06 | 实际会话来源：0无、1 USB、2屏幕 |
| P07 | bit7:0当前请求号，bit8当前号有效，bit16:9最后派发号，bit17派发号有效 |
| P08 | 阶段：0空闲或其他测试、1准备、2递进、3保持、4自动完成、5已停止、6失联、7错误 |
| P09 | 当前会话真实引擎成功完成数0..32，不是发出请求数 |
| P10 | 最后成功完成的MIDI音高；完成数0时为0，否则为47+P09 |
| P11 | 保留终态错误码：0正常、6失联、7引擎拒绝或未知结果 |
| P12 | bit5:0实际引擎声部数，bit10:8当前测试种类；声部数沿用原四拍观察流水 |
| P13 | 原看门狗期限750，单位ms |
| P14 | `0x13579BDF XOR P00 XOR ... XOR P13`，辅助检出漏字段 |
| P15 | `0x7`/24位递增快照序号/4位视图8，即 `(7<<28)|(seq<<4)|8` |

发布条件：收齐P00..P14、P15视图为8且标记正确、序号比上一已发布帧新、P14一致、能力标识和完整build匹配。中断或坏帧不发布；X/Z源状态不发布有效能力。P14是辅助字段一致性校验，不提供抗恶意篡改保证。快照序号按24位模数向前比较，间隔必须小于半个序号空间。

开始按钮记录请求号和此前实际session；回读必须属于新的实际session及该请求号。旧session、旧序号、旧请求号的状态都不能覆盖正在显示的新会话。终态由FPGA保留，不用屏幕计时动画推算32完成或自动完成。建议1秒未收到新的完整帧即显示连接状态未知并禁用开始；停止按钮仍可发送，未回读确认时显示“停止请求已发送，待设备确认”。复位后序号/session重新开始，清空旧缓存，重新检查能力；不重放旧启动命令。

## 音频参数

真实钢琴10、64模态和原精度、50MHz/48kHz不变。调度器请求间隔至少5,000,000时钟，背压会延后请求；32次真实成功完成后保持100,000,000时钟，再按公共panic链清音。自然衰减、吉他19、Bass20及混响算法不改。

屏幕控制使用实际会话与真实完成数回读；进度显示依据FPGA提交的原子快照更新。
