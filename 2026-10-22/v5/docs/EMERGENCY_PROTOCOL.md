# 上传期间紧急停止（WSV2 扩展）

## 能力查询

CAPS(0x30) ACK 第16～17字节是小端功能位：

| 位 | 含义 |
|---|---|
| 0 | RUNTIME_DETAILS |
| 1 | 曲谱与配器联合发布 |
| 2 | 本文的独立紧急通路 |
| 3 | 保留给逐轨混音；当前硬件不声明 |

不能把 bit1 当作逐轨混音能力。新上位机连接旧设备时不会发送未知紧急帧。

## EMERGENCY(0x3B)

沿用现有带 CRC16 的完整帧格式、16位序号和 ACK 原消息类型/状态字段。
负载恰好1字节：bit0清音，bit1取消资源事务，其余位必须为0，至少一位置1。

- `01`：立即停曲谱/试听/测试音，清除32旋律声部、鼓及效果器尾音；资源验证可继续。
- `02` 或 `03`：同样停音，并取消当前 DATA、验证、元数据或配器发布事务。
- 非法长度/位图：ACK 状态1，不执行动作。
- 合法命令：ACK 状态0。重试具有幂等性；动作先执行，ACK等待当前UART帧发完。

电脑“停止／全部停音”使用 `03`。清除旧排队的播放/试听请求；新用户操作可在停止确认后重新提交。
取消的资源事务不得继续发送 DATA 或 COMMIT。接收器会忽略该旧事务迟到的 ACK。

## FPGA 状态边界

- 资源解析状态机不参与紧急帧的接收；独立模块产生清音/取消脉冲。
- 普通ACK保留在资源模块已有的响应寄存器，紧急ACK仅缓存序号/状态；握手锁住后续普通请求，直到UART锁存普通响应。避免额外复制两份768位缓存。
- 串口整帧发送，不能破坏正在发送的CRC或字节；取消也会使电脑丢弃停止前的状态快照。
- 取消后清除资源缓存事务状态和重复ACK记录，释放验证器。
- 未完成歌曲/波表不发布。配器若已进入覆盖复制，则取消后把目标歌曲标为不可用。
- 本轮并未实现保留旧资源的原子替换；空间/替换策略仍属后续任务。
- 不重置BRAM大数组；只修改事务状态、目录标志和代际信息。

## 证据

`tests/test_serial_executor.py`：紧急帧越过慢COMMIT、ACK序号隔离、取消后不重试、关闭释放等待者、上传分块中止与旧设备兼容。

`tests/tb_workstation_v2_emergency.sv`：验证器持续busy、UART背压、非法帧、波表写入中止、后续PING恢复。

`tb_workstation_v2_integration`：32声部独立清音后可重新演奏。

`tb_workstation_v2_commands`：丢弃紧急停止前的排队播放命令。

这些是数字逻辑验证，不构成控制到模拟音频输出的整机延迟证据。
