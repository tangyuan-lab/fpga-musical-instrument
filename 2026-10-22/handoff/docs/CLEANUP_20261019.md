# 2026-10-19 比赛工程整理

## 原则与结果

将比赛日常工程与历史实验、工具、原始素材分开。原始工作目录约 **15.77 GiB、58147 个文件**。
完整旧目录保存在工程外 `_archive/github_cleanup_20261019/original_project/`；
不是永久删除，也不依赖不完整 ZIP 恢复。完整文件清单含每个原文件的大小与 SHA256，
放在同级 `original_full_inventory.json`。执行与核验记录同样在工程外归档。

当前工程只保留一个默认 `.gprj`，其余独立旧工程和失败/中断的实验随原目录归档。
原音源和参考 RTL 体积很小，对回归有用，保留在 `src/`，通过主工程 FileList 决定综合范围。
吉他候选参数独立保留在 `research/guitar/` 并标明未接入、未实板验收。

## 保留原件

- 全部29份参数/数学ROM：逐文件字节校验，不重新拟合、不改数值。
- v74 已试听位流：原字节与哈希保留，USER 0x00005AA4。
- 原钢琴+八鼓单声部和17音钢琴：原位流保留为回退，不当作四声部版本。
- v74 原冻结网表、约束：留在本地固件附件，可单独发布 GitHub Release。
- 数值报告、试听反馈、第三方来源与原授权文本。
- 全部原拟合脚本、研究文件、录音和诊断：完整原目录归档保留。

## 有意修改

1. 当前 RTL 中 FIR 参数加载由本机盘符路径改为项目相对路径，系数内容与运算表达式不变。
2. 默认构建时序约束明确为50MHz（20ns），原16ns目标单独保存。
3. 普通文本统一LF，ROM `.mem` 和冻结固件禁止 Git 自动改行尾，保留原字节。
4. 新建可配置 Gowin/Icarus 路径的构建与测试脚本，工具输出写入忽略的 `build/`。
5. 新 README 明确当前主工程、版本、四声部与实体键盘的范围，移走过时的“唯一单声部入口”说明。

## 验证

整理时的26项主工程输入完整；132项源文件内容核对；29份ROM与三份位流均通过哈希。
整理时记录的8项 smoke 回归、RTL 综合及128项映射后FIR系数检查属于当时快照。
随后发现打包源码中的宏调用和声明顺序问题，并在后续修复中调整；修复后的主工程已通过 ModelSim 10.6d 编译（24个Verilog文件，Errors 0，Warnings 0），但尚未重跑 Gowin 综合/布局布线或 Icarus smoke，也没有重新下载板卡。v74的实板证据与当前源码分开记录。

## 恢复

需要旧实验或拟合工作时，从 `original_project/` 拷贝到另一个独立目录继续，
先按清单验证哈希。原目录中的脚本可能含原机器绝对路径，不能只把某个脚本复制出来就假定可独立运行。
不要直接把整份旧目录覆盖当前工程，也不要把归档误上传成比赛源码。
