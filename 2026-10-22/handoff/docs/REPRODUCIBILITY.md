# 已试听位流与 RTL 构建的边界

## 已确认的 v74

v74 来源为冻结的 v68 修正网表，SHA256：
`677a8f7039d0638c78496c8481a60e1380d8bc6d4dbb2e3257bdc206c26e9c51`。
全量布局布线，未使用旧 .p/.pr，未加 GAO；20 ns 约束，route2、place2、开启资源复制。
USER 为 0x00005AA4，位流 SHA256：
`8e2318a08def7c6200c658e196b8b295555513fd32d5a44823d02075831be249`。

用户确认有声，进一步确认声音干净、没有颤抖；实际 USER 在反馈后再次读回一致。
本地交付包包含原位流、冻结网表、原管脚/时序约束和独立重建脚本。原文件未修改。
原位流通过 SHA256 定位，不能仅凭 USER 码判断新生成的文件与它字节一致。

## 当前 RTL

当前 `src/poly4_shared/shared_C_core.v` 使用显式完整字读取，保留已验证的参数和数值运算。
相同写法已有 128 项综合后符号检查及真实上电/按键 RTL 仿真证据，但不能把这些证据说成当前 RTL 已通过整机物理/音频验收。

整理仅将原 FIR 初始化文件的机器绝对路径改成项目相对路径；所有 .mem 文件逐字保留。
默认时序约束明确为实际 50 MHz；原 62.5 MHz 目标作为独立约束保留。
新源码构建使用 0x00005AB0，输出写入 `build/`，不覆盖或自动下载 v74。

## 旧静音问题

同一修正网表的旧 v68 静音，而全量重布后的 v74 有声且干净。这反对“修正逻辑必然静音”的结论。
四处 LUT 输出只进入 DSP A 数据端，本地握手控制与原 v61 一致。
旧物理实现/启动状态的具体故障尚未定位，不能宣称已有厂商确认的根因或稳定性保证。

旧静音位流、全部实验及原始报告保存在工程外归档，不作为推荐下载文件，也未混入本地可用位流列表。
