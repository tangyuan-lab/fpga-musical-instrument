# FPGA 资源与性能扩展记录

本文件记录同一套参数化架构在不同复音数下的资源、时序和满载输出表现，用于证明 FPGA 资源确实转化为有效复音、吞吐量、音质或效果。

## 测试一致性要求

每组数据必须注明：

- Git Commit；
- Gowin EDA 版本；
- 完整 FPGA 器件型号；
- 顶层模块和约束文件；
- 系统时钟、采样率和音频位深；
- 相位累加器位宽、波表深度和混音位宽；
- 是否使用 DSP、BRAM 以及共享或并行架构；
- 测试模式和满载持续时间。

除复音数外，比较组中的其他参数应保持一致。若参数变化，必须新建一组表格并解释原因。

## 吞吐量计算

官方评分口径采用：

```text
实时合成吞吐量 = 同时活跃且可闻的独立振荡器数 × 实际采样率
```

注意：

- 每个有效振荡器应具备独立相位状态、频率控制和包络控制。
- 同一个波形中的谐波不重复计算为复音。
- 过采样不会额外增加有效振荡器数量。
- 使用多频测试模式、输出频谱和 RTL 结构共同证明真实并行合成。

## 结论

待完成综合和满载测试后填写。结论必须解释资源变化、性能收益和工程取舍，不以接近 100% 利用率作为唯一目标。

到 2026-10-12 为止有五个数据点：0 复音基线（86 逻辑 / 0 BSRAM）、1 复音（305 逻辑 / 4 BSRAM）、
四音循环（313 逻辑 / 4 BSRAM）、2 复音（563 逻辑 / 8 BSRAM）、四声部引擎（1580 逻辑 / 0 BSRAM）。
可以看出两件事：

- 用波表的方案里，BSRAM 随声部数线性增长（每声部 4 块）。器件有 118 块，所以单靠波表最多约 29 个
  声部，够用但不是瓶颈的尽头；真正的瓶颈在逻辑和 Fmax——声部数翻倍时逻辑涨了约 84%，
  而 Fmax 从 100.733 MHz 掉到 79.748 MHz。
- 三角波引擎用算术生成波形，把 BSRAM 降到 0，四个声部只占 1255 LUT（3%）和 8 个 DSP。
  在同样的器件上这条路能走得更远，代价是逻辑和 DSP。

这些点之间架构不同（波表 / 算术、有没有混音级、有没有接输出链路），所以还不能把斜率直接外推到
8 或 16 复音。下一组数据应该固定一套架构，只改声部数。
